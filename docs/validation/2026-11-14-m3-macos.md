## 本轮发现与修复

1. macOS 的临时路径经过 `/var -> /private/var`，迁移的拒绝链接保护使默认测试失败。仅将验收子进程的 TMPDIR 设为真实路径，保留产品的链接拒绝边界。
2. 原 M3 包的 Notch 主题在真实 Mac 插件加载上下文中无法解析自定义控件。运行时 XAML 加载期间进入所属程序集的 contextual reflection 上下文，保留旧主题 ID 和资源 URI。
3. 共享 AI 服务没有参与中立入口的退出资源域。实例创建时登记 Dispose，正常停止取消后台预热；保留原四参数 SharedHostRegistration.Initialize，新增重载承接生命周期，兼容已有调用。
4. 原诊断验收仍禁止 M1 时代的所有可选依赖，误拒绝 M3 已共享的 SAI 接口。调整为非 Windows 平台禁止 Windows 依赖，并继续检查只有一个本机后端。

独立的 DesktopProbe 插件在宿主真实依赖解析、UI 线程和行动生命周期中验收；不向正式包注入测试代码。原包与修复包均记录结果，失败证据没有被覆盖成通过。

## 复验入口

在 SystemTools 根目录执行：

```bash
python3 eng/m1.py build --clean
python3 eng/m3.py check
python3 eng/m1.py test
python3 eng/check_reproducible.py
dotnet build tests/SystemTools.M3.DesktopProbe -c Release
```

本机工具链的宿主验收构建，版本参数需按实际机器重新核对：

```bash
python3 eng/m3_macos.py host-build --host-source <ClassIsland源码目录> --target-version 27.0 --minimum-version 14.0 --skip-xcode-version-check
python3 eng/m3_macos.py native-package --base-package <原M3.cipx> --output artifacts/m3/mac/SystemTools.M3.Mac.cipx
python3 eng/m3_macos.py smoke --host-bin <真实.app内宿主> --package artifacts/m3/mac/SystemTools.M3.Mac.cipx --label native
python3 eng/m3_macos.py smoke --host-bin <真实.app内宿主> --package <原M3.cipx> --label transferred
```

原包对照命令预期返回失败，因为它保留已确认的旧问题；不能将其退出码当作最终修复包失败。不要在 Mac 使用 Windows 专属的 m3.py package/smoke。人工观察可设置 `--observe-seconds`，该观察不替代结果文件中的正常退出。
