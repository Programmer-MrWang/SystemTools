## 迁移、恢复与数据边界

迁移页处理插件 JSON 配置，冲突项默认保留现有数据，导入后立即重启。宿主自动化、组件、通知和授权文件必须先退出宿主，再使用显式文件计划。转换只作用于登记身份字段、启用字典和指定布局引用；不全文替换用户文本。附件内容随原会话数据保留，外部附件路径不臆造改写；模型和依赖缓存不自动删除。

命令示例（从仓库根目录执行）：

    dotnet run --project eng/SystemTools.Migrate -c Release -- preview <计划.json>
    dotnet run --project eng/SystemTools.Migrate -c Release -- apply <计划.json>
    dotnet run --project eng/SystemTools.Migrate -c Release -- resume <journal.json>
    dotnet run --project eng/SystemTools.Migrate -c Release -- rollback <journal.json>

计划顶层包含 TargetRoot 和 Files；每个条目包含 Source、Target、Choice。Choice 使用 KeepExisting 或 ImportLegacy，默认 KeepExisting。用户选择保留与导入后才写入，不自动覆盖两份冲突配置。

迁移先备份、写候选与日志，再逐文件原子提交。中断可 resume；rollback 校验当前值并按字节恢复含 BOM 的旧文件；普通配置保存与迁移共享文档锁；预览后文件变化会拒绝写入。所有目标限制在 TargetRoot，拒绝链接路径。回退源码不等于回退数据，升级前快照应独立保留。
