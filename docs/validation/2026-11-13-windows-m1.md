## 本轮发现与修复

- 复制到 Windows 后，32 个中文资源路径缺失。对有内容相同文件的 25 项仅恢复名称；其余 7 项由 Git 精确恢复，均核对交接快照 SHA-256。用户原有 IDE、旧跨平台源码/调试包改动及子模块状态保留。
- 旧测试器在同一进程删除已被真实非 collectible 宿主加载上下文加载的 DLL，Windows 抛 UnauthorizedAccessException。现在为异平台损坏、本平台缺失分别创建目录，Python 在测试进程退出后清理；未修改宿主解析器快照或产品加载逻辑。
- 拷贝的 Mac obj 仍有 LF 生成源码；dotnet clean 使用旧绝对路径清单，可能先报 NETSDK1064，或遗留生成文件，使 Windows 两检出 DLL 不一致。显式 --clean 现在只删除入口、Contracts、本机后端经路径检查的 bin/obj，再 restore/build；其他系统后端、原版根项目、验收证据和宿主目录均不涉及。
- Path 的默认排序在 Windows 忽略大小写，在 POSIX 按大小写比较，导致相同源码指纹不同。改为相对路径各段的明确大小写排序，保持既有 Mac 指纹；新增一个固定输入的回归检查，打包测试由 9 项增至 10 项。

最终代码变化只有 eng/m1.py、eng/test_m1_packaging.py、tests/SystemTools.M1.Tests/Program.cs。src 及宿主生产源码未改；历史失败日志保留，最终成功日志另命名，没有用旧成功 JSON 代替本轮运行。

宿主日志中有后台请求失败，以及已捕获的 CompositionMaterial/WinUI renderer 首次机会异常；界面检查、按钮和工作流均实际成功，未观察到未处理崩溃或 fail/crit 事件。这些日志不当作本轮已修复的宿主问题。

## 复验入口

在 SystemTools 仓库执行：

~~~powershell
python -X utf8 eng/m1.py build --clean
python -X utf8 eng/m1.py test
python -X utf8 eng/test_m1_packaging.py
python -X utf8 eng/check_reproducible.py
~~~

宿主另行执行 dotnet build ClassIsland.Desktop/ClassIsland.Desktop.csproj -c Debug。三项 smoke 继续使用上面的原始 CIPX，参数见 m1.md；务必使用独立 sandbox。
