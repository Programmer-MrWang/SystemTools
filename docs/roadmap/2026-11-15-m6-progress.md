# M6 逐批记录

## M6.0：契约和接手基线

建立背景帧/坐标、OCR、原生材质、显示布局事务、硬件亮度分类契约。原有行动 ID 和 Windows 实现保持兼容；硬件背光、DDC 与软件变暗分别建模。显示布局必须提供回滚租约，不默认永久应用。

自审：发现能力探测不能隐式请求 TCC、触发外屏模式或启动提权；契约保持只读探测与显式执行分离。ClassIsland 和用户原 dirty 不纳入暂存。

后续各批完成后在此追加检查和自审证据。

## M6.1：排除自身的背景捕获

Mac 使用 ScreenCaptureKit 按整个宿主进程排除应用窗口，输出带实际像素尺寸的内存 PNG；区域采用全局逻辑点，按目标屏幕缩放处理负坐标和 Retina。跨屏、不合法区域、过大像素、权限缺失与超时明确失败。Linux 保持不可用，不用普通根窗口截图假冒背景。

检查：Release 解决方案零警告/错误；既有 M5 回归 252 项通过（含原生编译和助手 IPC）。自审：采集不写磁盘，不隐式请求权限；取消后拒绝消费迟到结果，串行化采集避免定时重入。实际屏幕排除验收并入 M6.8 原版宿主探针，不以本轮编译代替。

## M6.2：背景明暗主题

接入主界面组件实际区域，原生转换为屏幕逻辑坐标，避免直接除以 Retina 缩放导致多屏错位。两帧稳定判定和 112—144 迟滞带抑制闪烁；串行轮询、取消、故障及关闭恢复原主题，用户手动修改主题立即停止插件接管。兼容原行动 ID 与 enable/notifyOnExecute 字段。

检查：Mac Release 零警告/错误，十项专项检查通过；Linux 后端与共享宿主编译通过。自审：主题快照只在实际接管时建立，恢复前核对仍是插件写入值；隐藏后的 OCR 采样接口留给下一批，不将截图权限成功等同于 OCR 支持。

## M6.3：Vision 文字避让

Mac 原生 Vision 在内存背景图上识别中英文，只回传位置和置信度，不回传或保存文字。置信度 0.6、区域交集和最小文本尺寸过滤；连续两次命中隐藏，连续三次无文字恢复。隐藏时保留布局坐标继续采样，关闭/错误/停止恢复仅由插件隐藏的窗口。兼容原行动 ID 及原设置字段；手动接管可见性时停用避让。

检查：Mac Release 零警告/错误，14 项专项检查通过。自审发现初次未达到隐藏阈值时不能清空计数，已修正；用户原本隐藏的窗口不会被插件强制显示。Linux 因缺少可靠的排除自身背景链而保持不可用。

## M6.4：Mac 系统玻璃与材质

自有浮窗和对话窗口接入 NSGlassEffectView（macOS 26+），旧系统使用 NSVisualEffectView；通过原生 contentView 包装 Avalonia 内容，并在租约释放时恢复原有内容。系统减少透明度/增强对比度变化实时切换实色表面。Linux 没有通用模糊协议时显示实色并解释退路，不伪造原生玻璃。原 Windows shader 保留。

检查：13 项真实 AppKit 原生安装/命中/释放检查通过；Mac Release 零警告/错误。自审：玻璃使用 contentView 承载而不是任意兄弟叠层；一个窗口只允许一个租约，关闭解除观察器并恢复原始视图。完整 Avalonia 实际按钮与跨屏外观验收并入 M6.8；不把原生视图命中测试等同于实际宿主外观认可。
