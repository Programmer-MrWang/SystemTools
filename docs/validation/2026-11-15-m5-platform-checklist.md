# M5 对应平台实机验收

本清单区分已实现的代码、原生 CI 与设备成功路径。Windows 上的真实摄像头、麦克风、媒体会话和本地对话夹具证据见同目录 M5 Windows 验收；以下项目不能由 Windows 编译结果代替。

## Mac ARM64

1. 使用 M 系列 Mac 和原生 ARM64 ClassIsland。先核对最终 CIPX 的 SHA-256、清单中的三个 native stage、SDK 10.0.403 和代码提交。不要用旧 M3/M4 桌面探针的能力断言验收 M5。
2. 对照 `eng/host-patches/classisland-m5-media-permissions.patch` 确认宿主 Info.plist 已含 `NSCameraUsageDescription`、`NSMicrophoneUsageDescription`；本补丁没有交付到官方远程。应用补丁需 `git apply --unidiff-zero`。正式签名、entitlement 和 bundle 权限归属须在最终宿主验证。
3. 在“相机、语音与媒体”中显式申请权限。分别验证首次允许、拒绝、系统设置撤销、重新允许。缺少用途声明时应提示更新宿主，不直接请求设备访问。
4. 检查设备，使用返回的真实设备 ID 配置旧摄像头抓拍行动。连续两次抓拍得到不同文件名、可解码 PNG；设备占用、断开、取消和宿主退出时无半成品、设备灯熄灭，之后可再次采集。
5. 选择完整、语言匹配的 Vosk 模型，麦克风保持 `default`，在系统声音设置选择输入。验证实际 16 kHz 单声道 PCM 转换、识别、停止、重复开始、设备拔出和权限撤销，观察转换错误或缓冲积压后的明确反馈。
6. 验证后台关键词重复抑制，开始听写/对话时等待旧采集结束，退出后恢复关键词；同时打开两个前台消费者时明确拒绝第二个。
7. 配置兼容 AI 端点/模型及本次运行密钥。验证文字对话、实际语音识别、系统朗读、外放回声、用户打断、请求取消、网络错误、关闭窗口和应用退出。确认被打断的旧回复不会进入界面或继续朗读；重新启动后密钥需要重新输入。
8. 使用当前用户系统认证，验证真实成功、取消、切换认证项、关闭认证窗口、失败和迟到回调。取消后不得完成授权。新增身份为 `systemtools.authProviders.systemAuthentication`，不改写 Windows Hello 身份或旧密文。
9. 检查 Mac 通用媒体播放规则和原生歌词入口未作为已支持能力开放。

## Linux x64 原生 X11

1. 使用原生 x64 X11 桌面和最终包，保留用户配置。原生构建/公共回归已有 CI，真实 GNOME/KDE、V4L2、PulseAudio/PipeWire 桌面会话仍需要实测。
2. 准备 FFmpeg、可访问的 `/dev/video*` 设备、PulseAudio 兼容输入、语言匹配的完整 Vosk 模型；FFmpeg 可在设置中显式指定，错误路径应明确失败。
3. 检查设备并用返回的实际 ID 抓拍。验证成功、重复进入、权限不足、占用、拔出、取消、退出和无残留 FFmpeg；不要为测试修改系统设备权限。
4. 默认录音使用 `default`，也可显式指定 PulseAudio 输入。验证实际识别、设备切换/拔出、关键词与前台互斥、暂停恢复、取消和停止。对应进程应退出，不能只记录“未抛异常”。
5. 准备 `espeak-ng`，检查实际朗读、外放回声与打断；对话、审批、网络失败及会话密钥检查同 Mac。
6. 在当前用户 D-Bus 会话使用 `playerctl`。验证无播放器、播放、暂停、播放器切换/退出、会话服务消失和注销；错误后规则不得保持旧的播放状态。
7. 显式选择与当前曲目对应的 LRC 文件，验证真实进度、偏移、多时间标签、暂停/跳转、文件删除和错误内容。没有真实进度或歌词来源时清空显示；切换曲目需同步选择对应文件。
8. Linux 系统认证按计划不支持，任何失败/调用均不得放行。

## Windows 仍需本人或外部条件

- Windows Hello 的本人实际成功及人工取消；本机已确认 Available 和无父窗口拒绝，但没有代替用户完成生物认证或 PIN。
- 用户实际语言/麦克风内容及实际商业或自有 AI 服务。当前真实 Vosk 验证使用官方英文模型和音频，HTTP 流程使用本机确定性夹具，均不代表某外部模型的质量或可用性。
- 人工拔出设备、系统层撤销麦克风/摄像头权限、外放回声与长期使用、Windows 原有 Dlib 人脸/真实歌词来源的用户数据路径，需要对应硬件和本人配合。相机抓拍通过不能写成人脸认证通过。
