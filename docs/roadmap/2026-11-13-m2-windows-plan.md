# M2 Windows 完整业务接入计划

日期：2026-11-13。状态：计划，尚未开始业务迁移。唯一主开发目录为 SystemTools，分支 codex/cross-platform；SystemTools-Cross-platform 只作实现参考，ClassIsland1 是宿主。

目标：把 Windows 原版完整行为接入现有中立入口和 Windows 后端，同时保持正式 SystemTools 身份、旧配置、稳定 ID 和资源契约。每批先对照基线、实施最小改动、验收和审查，再按项目授权创建中文约定式本地提交。

## 进入条件与当前证据

Windows M1 已有 clean build、19 项加载检查、10 项打包检查、7 个跨目录一致输出、同一 Mac 包的三项宿主加载及 GUI/工作流证据。完整结果见 ../validation/2026-11-13-windows-m1.md。

2026-11-14 用户调整：Linux M1 完成代码与构建检查，不再要求真机测试，也不阻塞 Windows M2。Linux 实际运行仍如实标注未验证；三端相同 SDK 汇总和远端 CI 属于后续发行检查。按下列顺序继续 Windows 全量开发，每阶段验证后创建中文约定式本地提交。

验收宿主 runtimeconfig 已确认包含 Microsoft.NETCore.App 与 Microsoft.WindowsDesktop.App 10.0.0 框架引用，本机实际加载 10.0.10。这只解决本机 WinForms 框架存在性，不代表原版所有 Windows/native 功能已可用。

## 约束

- Windows 对照提交固定为 10a39f9db130ecaf38158e7fad8808dc3416acc3、标签 baseline/windows-2026-11-13。保留原项目作为回退和比较对象；不覆盖当前工作区或清理既有用户修改。
- 基线收录 62 个行动声明、7 触发器、7 组件、5 规则、3 主题、2 授权器、6 设置页、6 类集成及 70 个设置源码契约。声明数量不是全部实际注册数量；必须同时对照条件开关与注册调用。
- 沉浸式时钟按已确认产品例外不迁入；ClickSimulation 仅有源码声明、原版未注册，继续保留而不自动开放。
- Windows 普通退出无条件 shutdown /a 保持；系统关机/注销路径与普通退出分别核对，不借迁移更改既有策略。
- 不同时改 UI、配置格式和业务行为。从旧跨平台仓库取用缺陷修复时，结构移动和行为修复分开审查。
- ID、组件 GUID、通知及认证提供方、主题 ID、avares URI、设置键和密文不因程序集移动改变。DPAPI 仅在 Windows 处理；不可用功能不删除已有凭据或配置。
- 中立入口公开类型、静态初始化和 XAML 不依赖 Windows/native 类。Linux/Mac 未实现项不提供新建入口，已存在配置仍保留并提供明确诊断。
- 当前仅制定计划，不把本次 Windows M1 通过计为 Windows 原版全功能通过。

## 首批需要落实的技术决定

1. 后端注册协议应沿用现有 DI 与宿主注册扩展，仅添加实际迁移需要的能力。先检查现有模式，再决定 Contracts 需要新增哪些方法；避免一次设计所有 OS 服务。
2. 原代码若移动到 SystemTools.Platforms.Windows，旧 avares://SystemTools/... URI、序列化类型名和程序集身份可能改变。必须先做资源及类型兼容样例，选择保留入口资源、兼容转发或其他经宿主验证的最小方案，再批量移动；不能只替换命名空间。
3. 原项目有构建后 SAI 调试同步目标。基线构建与迁入后默认构建都不得写日常宿主路径；使用显式测试路径/开关验证可选接入，不复制历史 Mac 或个人 Windows 绝对路径到生产默认值。
4. 不把旧 EnsureOptionalDependencyState 的“缺依赖清理认证项”直接搬成跨平台通用清理。根据既定保留策略区分不可用与用户明确删除，验收以凭据副本无损为准。
5. 原源码修复来源应逐个标注，优先核对 DirectoryTransfer、ActionRestoreStore、WorkflowTargetResolver、ShutdownPlanState、PowerCommandRunner 的语义是否适用于原 Windows；不因参考版本已有检查就自动视为迁入版本通过。

## 每批通用验收

- 编译：干净本机构建；有平台/打包边界变化时复跑对应 M1 检查；输入变化后重新验证源码指纹和汇总。
- 契约：行动 ID/GUID/主题与资源 URI/配置键与默认值；不存在重复注册或静态泄漏。
- 运行：支持功能在 Windows 成功，拒绝/缺依赖明确反馈，取消/中断/恢复/普通退出正确。
- 数据：使用真实序列化器回写独立副本；比较字段、密文和旧配置；不将 M1 的字节未改证明当作 M2 的迁移成功。
- 证据：报告区分已经运行、静态检查与待硬件验证，记录实际 SDK、宿主与包哈希。
- 审查：只纳入本批相关文件，保留 IDE 与参考仓库已有修改；本地提交与推送、发布分别按明确授权处理。

## M2 完成标准与下一步

M2 完成需要 Windows 现有开放功能逐项保真、旧配置可用、可选依赖失败边界和退出清理完整、三端入口隔离不退化。沉浸式时钟与未注册 ClickSimulation 按上述约定单列，不能用隐藏其他 Windows 功能降低验收要求。

下一步先补 Linux M1 与统一工具链汇总，同时准备 M2-0 的原版 Windows 实测矩阵；进入实施后的第一条代码链路是 M2-1 的 SystemTools.OpenAppSettings。更大范围的跨平台配置迁移属于 M3，Linux/Mac 真实业务扩展属于 M4 之后。
