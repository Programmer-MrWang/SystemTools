# M5 执行顺序：摄像头、语音、认证与媒体

日期：2026-11-15。依据统一路线图第 M5 节。本文保留 M4 收尾时制定的 M5 计划。现已完成 M5 开发、新三平台原生构建/同源合包及本台 Mac 可完成的验收，详见 ../validation/2026-11-15-m5-closeout.md。ClassIsland 源码始终不改，Mac 采集由插件自带独立助手完成；其他系统和无法代替本人/硬件完成的项目仍单列 pending。

## 批次及依赖

| 顺序 | 批次 | 交付及进入下一批的条件 |
| --- | --- | --- |
| 1 | M5.0 能力与资源约定 | 核对旧 ID/配置、宿主权限声明、原生依赖与模型分发；定义相机/录音所有权、取消和停止边界，平台不可用时准确反馈 |
| 2 | M5.1 摄像头单次抓拍 | 先完成明确设备的一张图片：授权、占用、输出校验、取消和退出释放；Windows 原行为回归后，再在 Mac/Linux 对应环境验证 |
| 3 | M5.2a 语音听写 | 先验证原生采音和一次识别成功，记录语言、模型/在线依赖、输出；缺模型、拒绝权限、设备拔出及取消均可退出 |
| 4 | M5.2b 关键词与唤醒 | 复用录音所有权管理，验证重复触发抑制、听写/唤醒竞争、暂停恢复、停止退订 |
| 5 | M5.2c 对话与打断 | 在前两批稳定后接入会话，验证播报时的采音策略、打断、取消、网络失败及宿主退出；保留已有 AI 工具审批 |
| 6 | M5.3 系统认证 | Windows Hello 保留并回归；Mac 接系统认证；取消/失败不得放行，不修改或抹去旧密文；Linux 无可靠后端时保持不可用 |
| 7 | M5.4 媒体与歌词 | 先 Windows/Linux 播放状态规则，再按真实来源接歌词；验证播放/暂停、会话切换、服务退出和注销；Mac 无已验证后端时不开放 |
| 8 | M5.5 集成关闭 | 共享回归、三端原生构建/同源合包、明确范围的真实桌面与设备验收、配置往返、停止清理和阶段记录 |

前半段先做相机的小闭环，再逐级增加语音的长期状态和并发，最后接认证与媒体。听写、唤醒和对话共用录音所有权；不要为三个功能各开一个相互争用的麦克风会话。

## 先读的现有代码

- 摄像头：`Services/CameraCaptureService.cs`、`Actions/CameraCaptureAction.cs`、`Settings/CameraCaptureSettings.cs`、Windows 可选依赖入口。抓拍通过不等于人脸识别通过；人脸成功路径另列，需要模型与真实设备。
- 语音：`Services/VoskSpeechService.cs`、`Services/KeywordSpeechService.cs`、`Services/AiVoiceConversationService.cs`、`VoskWorker`，以及相应唤醒行动/设置。
- 认证：`Services/WindowsHelloService.cs`、`Settings/WindowsHelloSettings.cs` 与现有授权入口。
- 媒体：`Rules/Handlers/MediaMusicPlayingRuleHandler.cs` 及歌词现有来源适配。

Windows SAPI/Worker 可以继续保留。Mac/Linux 的采音、识别与模型后端在 M5.0/M5.2a 对应批次重新核实，不把 win-x64 Worker 改名当成跨平台后端，也不提前承诺具体识别引擎。

## 每批关闭要求

先读现有实现和平台约束，说明本批写入范围，再实现最小闭环；跑相关编译、契约与目标平台实测，自审后中文约定式提交并通过本机代理推送。原有 dirty 文件继续保留，不自动发布。

每批分别记录 implemented、available 与 runtimeVerified。实测至少包括成功、拒绝权限、设备占用/移除、取消、重复进入、宿主停止和无残留资源；未具备设备或目标系统时明确 pending。M4 的 Mac 最小化、多屏/Spaces、真实 USB/热键/锁屏及 Linux 桌面验证仍按 M4 清单独立追踪。
