# M4 推进计划：Mac ARM64 与 Linux X11 基础原生能力

日期：2026-11-14，Asia/Shanghai。状态：计划，尚未开始实现。前置验收见 `../validation/2026-11-14-m3-macos.md`。

目标是在现有 SystemTools 正式身份下，逐项接入系统音量、空闲、截图、设备、输入、窗口和壁纸。每项都完成能力检测、设置、执行、取消或恢复、失败反馈与退出清理；Windows 原有行为、稳定 ID、配置和密文保持兼容。

主仓库仍为当前 SystemTools 的 `codex/cross-platform`。ClassIsland 为宿主契约来源，SystemTools-Cross-platform 只供参考。Mac 仅原生 ARM64，Linux 首轮仅 x64 原生 X11。M4 不自动扩展到语音、摄像头、人脸、Windows Hello、Keychain/Secret Service 或复杂玻璃效果。

## M4.0：先固定原生接入边界

1. 对照 `FeatureCatalog`、`PlatformContract`、`SharedHostRegistration`、中立入口和 Windows 后端，写清每项服务的注册位置、线程、句柄所有者与关闭顺序。
2. 当前入口遇到 `IPlatformPlugin` 就交由后端完成初始化；否则才注册 SharedHost。给 Mac/Linux 增加原生注册时必须保留共享业务且只初始化一次。先确定最小接入方式，再改入口，不直接照搬 Windows 完整插件初始化。
3. 公共设置与行动包装留在 SharedHost，平台实现留在各后端；Common 保持纯逻辑。只为真实平台差异增加窄接口，不为每个按钮建新工程。
4. Mac 优先核查现有宿主服务和系统 C API 能否满足要求。确需 Objective-C/Swift 桥接时，再增加仅本机编译的 ARM64 资产；中立工程不得被迫安装其他系统 SDK。
5. 区分未实现、缺依赖、缺设备、权限未授予和要求重启。发现能力只读；实际请求权限必须由明确操作触发。权限撤销后下次执行重新判断。
6. 检查签名与 TCC 归属：真实 .app、进程架构、数据目录、Bundle ID 和权限记录要对应。M3 的 macOS 27.0/min14.0 本地覆盖不能变成未经说明的正式最低版本。
7. Linux 检查 XDG_SESSION_TYPE、DISPLAY、WAYLAND_DISPLAY 和 X11 连接；Wayland/XWayland 继续明确拒绝。列出音频、Xss、XTest、D-Bus/udev 等具体依赖及缺失提示。
8. 固定验收数据目录和恢复方法。音量、壁纸与输入的实测使用明确测试目标；退出、取消及测试失败均需要释放原生资源。

完成条件：形成服务/能力/权限矩阵；默认 Mac 构建只编译本机后端；M3 的设置页、六组件、主题、文件、迁移和退出回归继续通过。此批不开放新菜单。

建议提交：`docs(m4): 固定原生能力接入与权限矩阵`，随后按实际需要单独提交最小契约改动。

## M4.1a：系统主音量，作为第一项完整闭环

稳定 ID 为 `SystemTools.SetVolume`，现有设置字段为 `volumePercent` 和 `notifyOnExecute`。不可误用不存在的 `SetSystemVolume` 身份，也不把播放器音量称为系统音量。

- Mac：Core Audio 默认输出设备；检测音量属性是否存在且可写，执行前再次取得目标设备。HDMI、聚合设备或固定音量设备不可写时明确报告，不伪造成功。
- Linux：优先评估 PulseAudio 协议兼容后端，覆盖 PulseAudio 与运行 pipewire-pulse 的系统；若选择独立工具，缺工具应报告 MissingDependency。原生 PipeWire 作为单独能力，不能靠系统名称推断可用。
- 保留旧设置及默认值，限定 0–100%，处理非有限数值；设置完成后读回，反馈真实结果和设备变化。
- 先保持 Windows 现有不可恢复行动语义。若新增平滑调节或恢复选项，独立定义兼容设置和持有者快照，不顺手改变 Windows 既有行为。
- 多个行动并发、默认设备切换、设备拔出和静音状态要有确定行为；取消/停止不能继续写入设备。

验收：真实设备读取→小幅设置→读回→恢复原音量；固定音量设备、设备消失、后台取消与正常退出；设置/菜单/AI/SAI 使用同一能力结果。Mac 实机证据与 Linux 代码/构建证据分别记录。

建议提交：契约和共享包装、Mac 后端、Linux 后端、验收记录分别提交。

## M4.1b：空闲触发器

稳定 ID 为 `SystemTools.LongIdleTrigger`。对齐现有 Windows 规则：至少一分钟阈值、越过阈值只触发一次、恢复操作后按行动流的恢复开关调用恢复。

- Mac：评估 Quartz 的事件空闲时长接口，区分系统事件源与进程局部事件；验证锁屏、睡眠唤醒和长时间运行。
- Linux：XScreenSaver/Xss 查询原生 X11 空闲时长，检测扩展可用性和 DISPLAY 断连。
- SharedHost 承担阈值状态机与防重入；每个触发器实例单独持有轮询和取消资源。Loaded/UnLoaded、重复加载和配置改变不能叠加定时器。
- 原生查询失败不能当作用户刚操作，也不能每秒刷错误或反复触发。使用明确不可用状态并在恢复后重新采样。

验收：阈值边界、重复采样、重新活动、恢复开关、睡眠/唤醒、多个触发器、卸载后零回调。纯状态机用可控时钟；真实 Mac 另验证系统查询，不能用缩短阈值的单元测试代替全部实测。

## M4.2a：截图

先对齐原 Windows `SystemTools.ScreenShot` 的主显示器 PNG 与 `SaveFolder`/通知语义。多屏、窗口、区域截图作为显式扩展，不把宿主的窗口截图接口直接冒充全屏实现。

- Mac：评估 ScreenCaptureKit，明确屏幕录制权限、授权拒绝/撤销和锁屏状态；后端返回截图数据和真实尺寸，SharedHost 负责命名和安全写入。
- Linux：原生 X11 图像采集，处理像素格式、显示器尺寸和连接断开；不增加 Wayland portal 路线。
- 使用像素尺寸处理缩放，避免把 Avalonia 的逻辑尺寸当输出像素；连续截图文件名须防冲突。
- 输出先写临时文件，取消/失败清理半成品；权限失败不生成伪空图，也不报告成功。

验收：实际 PNG 可解码且尺寸正确、缩放/双屏主屏、非 ASCII/带空格路径、只读目录、连续执行、权限拒绝与撤销、采集中取消/退出。

## M4.2b：USB 与挂载

稳定 ID 为 `SystemTools.UsbDeviceTrigger`。先实现只读发现与事件，再接自动打开；不在本批跨平台开放原有禁用/启用设备行动。

- Mac：IOKit 设备通知与挂载卷通知分别建模；只监听 USB 存储时，要验证总线、卷就绪和多分区去重，不能只凭可移动盘标记。
- Linux：libudev 识别物理设备，UDisks/D-Bus 获取挂载状态；无总线/服务时返回具体能力状态。
- 共享去重按稳定设备身份，时间使用单调时钟；启动已有设备是否触发必须明确，避免每次重启都把全部设备当新插入。
- 设备插入但未挂载、快速拔出、同盘多个卷、多个设备并发、设置切换都要取消旧等待。
- 自动打开只在来源明确且卷已就绪时调用宿主启动服务；不把设备路径拼进 shell。日志不无谓记录序列号。

验收：真实 USB 插拔、多个分区只触发一次、同设备重新插入、不同设备并发、拔出取消、停止后零监听与零残留原生句柄。

## M4.3a：热键与输入

先接 `HotkeyTrigger`，再接模拟组合键与录制输入。保留 Windows 原始键值配置，同时新增明确的平台/逻辑键含义；旧 Windows VK 在 Mac/Linux 不能机械照搬，也不能被保存操作抹掉。

- Mac：先确定全局快捷键机制及冲突反馈；模拟输入采用 Quartz，核查 Accessibility/Input Monitoring 的实际要求与应用签名归属。
- Linux：XGrabKey 注册热键、XTest 发键，处理 NumLock/CapsLock 组合、键盘布局和抓取冲突。
- 区分物理按键、逻辑快捷键和 Unicode 文本。中文、组合字符、布局差异及 Command/Control 映射单独验收。
- 输入仅对明确选择的合成测试窗口执行。取消、异常或退出时释放已经按下的全部键；不可持续重试向未知焦点窗口输入。
- ClickSimulation 原版未注册，继续不新增；不自动恢复沉浸式时钟。

验收：冲突可见、重复注册/注销、键序与间隔、Unicode、取消时按键释放、权限撤销、测试窗口失焦、重启无残留热键。自动化测试不能向日常聊天或终端注入内容。

## M4.3b：窗口与浮窗

先列出 `WindowOperation` 每个子操作的目标和结果，不把找到进程等同于找到可操作窗口。

- Mac：Accessibility 定位可操作外部窗口，AppKit 处理自身窗口；明确 AX 窗口身份、消失、受保护窗口、焦点限制及主线程要求。
- Linux：EWMH/ICCCM 处理窗口管理器语义；检查 WM 支持项，失败不能只按发送事件成功判断。
- 对齐激活、最小化、恢复、关闭和尺寸操作；跨应用操作限制在显式选定测试窗口，不猜测同名目标。
- 当前 Mac 宿主 Bottommost 没有实际实现，GetWindowFeatures 也不能提供可靠状态。普通层级不可显示为“置底”；先保留不可用配置并准确提示。
- 浮窗的层级、主题和方案恢复复用持有者快照；同组多行动、跨组重叠和原窗口销毁都必须正确。

验收：真实自有测试窗口的每项操作、重复标题/PID 重用、窗口关闭、权限变化、层级切换与恢复、退出资源释放。宿主接口修改需要单独说明影响并提交。

## M4.4：壁纸与联动

稳定 ID 为 `SystemTools.ChangeWallpaper`。保留图片/纯色、路径和 FitStyle 设置；逐项列出哪些布局可以准确映射。

- Mac：NSWorkspace 与显示器身份，明确多屏/Spaces 的实际支持范围；跨屏填充等无法准确映射时反馈限制。
- Linux：明确首批桌面环境，例如 GNOME 与 KDE 各自适配；原生 X11 不等于所有桌面环境都支持相同壁纸接口。无适配器时保持 Unsupported。
- 图片校验、解码、取色和 ClassIsland 主题联动共享；平台侧负责实际桌面写入。纯色若通过生成图片实现，保存到持久目录并说明清理策略。
- 原壁纸与选择选项形成可恢复快照，恢复前确认目标显示器仍存在；不要覆盖用户在行动期间主动选择的新壁纸。
- 颜色提取失败与壁纸写入失败分别处理，避免壁纸成功却错误宣告全部联动成功。

验收：真实更换与恢复、图片损坏/路径不可读、外接显示器增减、连续切换、用户中途更改、主题/浮窗交错、取消/退出。只使用合成图片，不改日常配置做破坏性实验。

## M4.5：回归、打包与关闭标准

每个功能批次结束先跑本机默认构建、相关公共/后端测试和 M3 Mac 桌面验收，再审查稳定身份及共享代码的 Windows 依赖。核心检查通过后，不为凑数量重复相同测试。

完整包必须由同一提交、同一依赖版本的各平台输出汇总并检查公共程序集哈希；M3 的“Windows 外平台资产原样保留 + Mac 公共程序集替换”预览包不能直接改名成为 M4 正式通用包。

| 证据层 | 必须记录 |
| --- | --- |
| 纯逻辑 | 参数、状态机、恢复快照、取消、错误与配置往返 |
| Mac 本机 | SDK/Xcode/工作负载、真实 ARM64 .app、权限与设备、实际执行结果、正常退出 |
| Linux 代码与构建 | linux-x64 目标、X11 分支、依赖与契约测试；没有真机就维持 runtimeVerified=false |
| Linux 实机 | 有原生 X11 环境时补真实运行；此前 M1 的免真机决定不等于 M4 全部功能已实测 |
| Windows 回归 | 受共享改动影响的原行为；Mac 检查不能替代 Windows 本机结果 |
| 同包隔离 | 正常安装、异平台 DLL 损坏、本机后端缺失；宿主程序集不重复加载 |
| 数据与清理 | 配置/密文/未知字段保留；取消、卸载和正常退出；机器级 Global.json 哈希监测 |

阶段记录应列出每项能力的 implemented、available 与 runtimeVerified，保存包哈希、代码提交、真实执行 OS、成功和失败日志。未具备权限或设备的场景独立追踪，不能用“通过构建”替代。

每批按“读现有行为 → 小范围实现 → 相关检查 → 差异审查 → 中文约定式本地提交 → 更新记录”关闭。没有推送或发布授权。第一批具体动作是 M4.0 矩阵与接入方案，随后执行 M4.1a 系统音量。
